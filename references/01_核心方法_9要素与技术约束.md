# 01 · 核心方法：9 要素骨架 + 技术约束

> 本文件是技能的方法内核。**出稿前必读**。所有提示词=9 要素的填充。

---

## 一、黄金骨架：9 要素（可直接复制改写）

```
【角色】你现在是一位 ____（如：有 15 年教龄的初中物理教师 + 资深前端工程师）
【学情】面向 ____（学段+年级+教材版本+班级水平+前置知识）
【教学目标】围绕 ____ 知识点，达成 ____ 目标，突破的难点是 ____
【内容结构】划分 ____ 个板块：情境导入 / 新知探究 / 动手操作 / 巩固练习 / 课堂小结 / 拓展
【核心交互】学生能 ____（拖拽/滑块/点击/输入/排序/翻卡），操作后 ____（即时反馈/实时计算/动画演示）
【视觉风格】____ 风格（专业简洁/可爱卡通/古风/科技感），配色 ____，正文字号 ____，留白适合后排观看
【技术约束】输出单个 HTML 文件，CSS 与 JS 内联，无需联网，响应式适配大屏投影
【输出格式】直接输出完整可运行代码（<!DOCTYPE html> 开头，</html> 结尾），并在 JS 中注释标出可修改区域
【验收标准】① 知识点科学准确 ② 动画可暂停/重置 ③ 答对答错有反馈 ④ 双击浏览器即可打开
```

**记忆口诀**：谁来讲（角色）— 给谁讲（学情）— 讲什么（目标+结构）— 怎么玩（交互）— 长什么样（视觉）— 怎么跑（技术）— 交付形式（输出）— 怎么算合格（验收）。

## 二、九要素写法要点与正反例

| 要素 | 要点 | ❌ 反例 | ✅ 正例 |
|---|---|---|---|
| 角色 | 给 AI"穿工作服" | "帮我写教案" | "请扮演有 15 年教龄的小学数学特级教师……" |
| 学情 | 学段+年级+教材版本+班级水平+前置知识 | "给初中生" | "人教版八年级、基础中等，已学一次函数" |
| 教学目标 | 对应课标素养，点明重难点 | "讲一下勾股定理" | "经历操作→猜想→归纳→证明，突破面积法证明" |
| 内容结构 | 分板块、控时长、标过渡串词 | 只给主题 | "分 5 板块，总时长 20 分钟内，过渡页注明串词" |
| 核心交互 | 明确"学生能做什么"+"操作后反馈" | "加点互动" | "拖动滑块调直角边，三角形实时重绘并显示面积" |
| 视觉风格 | 配色（Hex）、字体、字号、留白 | "好看一点" | "蓝白两色，正文 24 号，标题 32 号加粗，每页 ≤6 行" |
| 技术约束 | 单文件 / 内联 / 响应式 / 离线 / CDN | （不写） | "输出单个 HTML 文件，CSS/JS 内联，无需联网，双击可运行" |
| 输出格式 | 完整文档、标注可改区 | （不写） | "从 <!DOCTYPE html> 到 </html> 完整输出，JS 中注释替换位置" |
| 验收标准 | 科学正确 / 可暂停重置 / 有反馈 / 大屏可读 | （不写） | "答错显示红叉+正确答案+解析；提供重置按钮" |

## 三、三条铁律（顺序不能颠倒）

1. **先定格式** —— 生成前第一件事先贴格式要求（字体/字号/配色/每页行数），比生成完再调省一半事。
2. **再喂学情** —— 指定教材版本 + 班级真实水平 + 前置知识；不喂学情必"水土不服"。
3. **最后锁死技术约束** —— "单文件 HTML、CSS/JS 内联、完整输出、无需联网"（通用大模型尤其必须）。

> 三个高频坑：不写视觉规范（投屏后排看不清）、不写学情（超纲或过浅）、不写结构（内容跑偏）。

---

## 四、三种上手流派（供改写时参考）

| 流派 | 适用 | 骨架 |
|---|---|---|
| **三段话** | 新手，最低门槛 | ①身份与对象 ②内容与结构 ③技术要求 |
| **四件套 + 紧箍咒** | 最简可复用 | 主题 + 人群 + 结构 + 风格；+ 强制页码结构 / 动词化标题 / 反向排除（"不要渐变、不要花哨动画、不要大段文字"） |
| **五步法** | 公开课/赛课，最系统 | 教研→大纲→文案→视觉→前端，分步产出，每步确认 |

> 本技能为**快速式**：默认直接用 9 要素一次组装；教师若要更细，可在输出后按五步法追问。

## 五、技术约束话术速查（可直接粘贴）

| 需求 | 话术 |
|---|---|
| 单文件 | "输出为单个 HTML 文件，CSS 和 JS 内联，确保完整输出，不要截断" |
| 离线可用 | "无需联网，双击即可打开运行" |
| 大屏适配 | "响应式适配大屏投影，字体层级分明，每屏留白合理，不出现滚动条" |
| 3D 模型 | "使用 Three.js 构建可旋转、可拆解的 3D 模型" |
| 2D 绘图 | "使用 Canvas/SVG 绘制，图形随参数实时重绘" |
| 公式 | "使用 MathJax/KaTeX 渲染公式" |
| 图表 | "使用 ECharts/Chart.js 绘制，数据变化时图表实时更新" |
| 朗读/听写 | "使用浏览器 SpeechSynthesis（Web Speech API，语音合成）实现朗读，可调语速" |
| 双端交互 | "同时支持鼠标（click）与触屏（touchstart）事件" |
| 可改区标注 | "在 JS 中注释标明可修改区域（如题目、图片路径）" |

> 依赖库尽量通过 CDN 引入；只引需要的库，不引大图，长内容懒加载。

## 六、迭代优化的五条通用动作

1. **追问式修改**：同对话补要求（"动画慢一倍""增加重置按钮""第 3 页换选择题"）。
2. **局部修改**：只改有问题的那页/那段，不推倒重来。
3. **追加约束**：把上次的问题写成新约束（"上次字号太小，这次正文统一 28 号"）。
4. **"做同款"起步**：平台资源广场找相似案例点"做同款"再改。
5. **指令过载排查**：生成失败/错乱时，先简化指令只留核心需求，再逐条加回；网络报错切网络重试。
